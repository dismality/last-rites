# Development Log Rule

This project is a hackathon entry, and judges score how Kiro was used. Keep `docs/kiro-log.md` up to date.

After finishing a spec task or any change that touches more than one file, append an entry to `docs/kiro-log.md`:

```markdown
### YYYY-MM-DD: <spec name> task <number>: <short title>
- **Kiro feature used:** spec task / hook / steering / MCP / PBT / Crew agent
- **What happened:** one or two sentences
- **What Kiro caught or sped up:** anything notable (a bug a hook found, a property test failure, a steering rule that prevented a mistake)
```

Keep entries short and factual. Do not invent events.
